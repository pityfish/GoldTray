# GoldTray 跨平台黄金行情监控工具设计文档

**版本：** V1.0  
**日期：** 2026-11-02  
**目标平台：** macOS / Windows  
**技术方案：** Tauri 2 + Vue 3 + TypeScript + Rust  
**产品定位：** 轻量级桌面黄金价格监控及持仓管理工具

---

## 1. 项目概述

### 1.1 项目背景

目前部分银行积存金产品缺乏方便的桌面实时行情显示和多条件价格预警能力。

用户需要反复打开手机银行查看黄金价格，无法方便地在电脑工作时持续观察市场变化。

本项目开发一款常驻系统托盘的跨平台桌面应用，提供黄金行情展示、自定义价格预警、持仓盈亏计算和历史行情等功能。

初期以招商银行黄金账户·活期为主要支持对象，后续通过可扩展的数据源架构支持其他银行和贵金属品种。

### 1.2 设计目标

1. 支持 macOS 和 Windows，使用统一代码库。
2. 在系统菜单栏或任务栏通知区域持续展示黄金价格。
3. 支持定时自动刷新行情。
4. 支持多个独立的上涨、下跌价格预警。
5. 支持记录黄金买卖交易及计算实际持仓盈亏。
6. 应用关闭主界面后仍可驻留后台。
7. 支持开机启动、系统原生通知。
8. 无需个人银行账户登录。
9. 本地优先，无须部署后端服务器。
10. 保证行情数据来源清晰，禁止将第三方参考价伪装为银行官方实时成交价。

### 1.3 非目标范围

V1.0 不包含：

- 自动购买或卖出黄金
- 银行账户登录及授权
- 自动同步银行持仓
- 高频交易
- 复杂的量化交易策略
- 云端账户系统及多设备同步

## 2. 技术选型

### 2.1 技术栈

| 层次 | 技术 | 用途 |
|---|---|---|
| 桌面框架 | Tauri 2 | 跨平台桌面运行环境 |
| 前端框架 | Vue 3 | UI开发 |
| 编程语言 | TypeScript | 前端逻辑及数据类型 |
| UI组件 | Naive UI | 设置页、表单、弹窗 |
| 图表 | ECharts | 历史价格走势图 |
| 状态管理 | Pinia | 页面状态管理 |
| 核心服务 | Rust | 后台轮询、托盘和规则引擎 |
| 网络请求 | Rust HTTP客户端 | 获取行情数据 |
| 数据存储 | SQLite | 持仓及行情历史 |
| 配置存储 | Tauri Store | 应用配置 |
| 原生通知 | Tauri Notification | 到价通知 |
| 自动启动 | Tauri Autostart | 系统登录后启动 |

具体依赖版本在初始化项目时锁定，避免使用已经废弃的插件API。

### 2.2 选型理由

Tauri 2 相比 Electron 更适合此类应用：

- 不需要额外捆绑完整 Chromium。
- 可以复用 Vue 和 TypeScript 前端开发经验。
- 能使用 Rust 管理后台任务。
- 适合开发常驻托盘的轻量程序。
- 可为 macOS 和 Windows 分别打包原生安装程序。

由于系统托盘标题、图标和通知在不同系统上的行为不完全一致，需要保留平台适配层。

### 2.3 操作系统兼容性

| 平台 | 目标版本 | 关键实现 |
|---|---|---|
| macOS | macOS 13及以上 | Menu Bar 状态栏图标和标题 |
| Windows | Windows 10/11 | 系统托盘图标及悬停提示 |

首版优先支持 Apple Silicon 和 Windows x64。

Windows 系统托盘不保证能像 macOS 一样持续显示完整的金价文字。因此 Windows 使用动态托盘图标、鼠标悬停提示及点击弹窗显示行情。

## 3. 系统架构

### 3.1 总体架构

```text
┌──────────────────────────────────────┐
│          Desktop Application         │
│                                      │
│  ┌────────────────────────────────┐  │
│  │          Vue 3 UI              │  │
│  │                                │  │
│  │  行情展示 / 价格预警 / 持仓管理    │  │
│  │  历史行情 / 设置管理             │  │
│  └────────────────┬───────────────┘  │
│                   │ Tauri IPC         │
│  ┌────────────────▼───────────────┐  │
│  │           Rust Core            │  │
│  │                                │  │
│  │  QuoteService                  │  │
│  │  AlertEngine                   │  │
│  │  PortfolioService              │  │
│  │  TrayManager                   │  │
│  │  NotificationService           │  │
│  │  Scheduler                     │  │
│  └─────────────┬─────────┬────────┘  │
│                │         │           │
│           HTTP API     SQLite        │
└───────────────┼─────────┼───────────┘
                │         │
      ┌─────────▼───┐  ┌──▼──────────┐
      │ 第三方行情源 │  │ 本地持久化   │
      └─────────────┘  └─────────────┘
```

### 3.2 模块划分

**QuoteService**

负责请求行情接口、解析数据、规范化价格、判断数据有效性。

**AlertEngine**

负责价格规则判断、触发去重、冷却时间和预警状态管理。

**PortfolioService**

负责交易记录、黄金份额、持仓均价和盈亏计算。

**TrayManager**

负责 macOS 菜单栏和 Windows 托盘图标、标题及交互行为。

**NotificationService**

负责跨平台系统通知，包括提醒内容生成和通知权限检查。

**Scheduler**

负责定时行情获取、暂停恢复、重试与任务生命周期。

## 4. 行情数据源设计

### 4.1 已验证的数据源

数据提供方：汇率速递

接口：

```http
GET https://api2.huilvsudi.com/app-api/mp/quote/list?tab=gold&bank=CMB
```

验证请求：

```bash
curl -sS \
  'https://api2.huilvsudi.com/app-api/mp/quote/list?tab=gold&bank=CMB' \
  -H 'Accept: application/json' \
  -H 'tenant-id: 1' \
  -H 'terminal: 20'
```

示例响应：

```json
{
  "code": 0,
  "data": [
    {
      "id": 112,
      "bank": "CMB",
      "bankName": "招商银行",
      "currency": "GOLD_DEMAND",
      "currencyName": "黄金活期",
      "sellingPrice": "838.70",
      "change": 0.6800,
      "favoriteFlag": false,
      "favoriteTime": null
    }
  ],
  "msg": ""
}
```

该响应来自2026年11月2日的一次实际测试。

经用户在招商银行App中核对，`sellingPrice` 与当时黄金账户客户买入价一致。

但这一验证不能保证之后始终同步，也不能证明该接口是招商银行官方开放API。

### 4.2 字段映射

| 来源字段 | 内部字段 | 说明 |
|---|---|---|
| bank | bankCode | 银行代码 |
| bankName | bankName | 银行名称 |
| currency | productCode | 产品编码 |
| currencyName | productName | 产品名称 |
| sellingPrice | customerBuyPrice | 客户买入参考价 |
| change | rawChange | 原始变化值，语义待验证 |

当前接口没有返回明确的客户卖出价和报价时间，不得自行认为两者已存在。

### 4.3 内部行情模型

```typescript
interface GoldQuote {
  source: string;
  bankCode: string;
  productCode: string;

  customerBuyPrice: string;
  customerSellPrice?: string;

  rawChange?: string;

  currency: "CNY";
  unit: "GRAM";

  fetchedAt: string;
  quotedAt?: string;

  status: "LIVE" | "DELAYED" | "STALE";
  isEstimated: boolean;
}
```

说明：

- 价格使用十进制字符串，避免浮点运算精度问题。
- `fetchedAt` 表示本地成功获取响应的时间。
- `quotedAt` 仅在行情源明确提供报价时间时赋值。
- `LIVE` 表示近期成功获取有效响应，不保证源头行情毫秒级实时。
- 第三方估算报价必须设置 `isEstimated=true`。
- 如果无法获取官方卖出价，`customerSellPrice` 保持空值。

### 4.4 行情刷新策略

建议默认刷新周期：60秒。

支持设置：

- 30秒
- 60秒（默认）
- 120秒
- 300秒

实际提供的刷新选项应受数据源使用条款和限流条件约束。如果未获得高频调用许可，正式发行版本应采用更保守的刷新间隔。

**刷新规则：**

1. 应用启动后发起首次请求。
2. 请求成功后更新行情和托盘显示。
3. 同一时刻只允许一个行情请求进行。
4. HTTP请求超时设置为10秒。
5. 请求失败采用退避重试机制。
6. 连续失败时显示数据异常。
7. 系统休眠恢复及网络恢复后重新检查行情。
8. 非交易时段可以降低刷新频率。
9. 不依赖固定的交易时间来判断数据是否有效，优先检查报价时间和行情源状态。

### 4.5 价格有效性校验

必须满足：

- HTTP请求成功。
- JSON解析成功。
- `code == 0`。
- 存在招商银行黄金活期对应记录。
- `sellingPrice` 是合法正数。
- 与上一笔价格相比无明显异常，或者异常已被二次确认。

当新价格变化超过配置的异常波动阈值时，先重新获取并确认，再触发交易价格提醒。

不能简单地把超过某个涨跌幅的真实行情全部拒绝。

### 4.6 数据源接口抽象

```typescript
interface GoldQuoteProvider {
  getId(): string;

  fetchQuote(): Promise<GoldQuote>;

  supportsBuyPrice(): boolean;

  supportsSellPrice(): boolean;
}
```

V1.0 实现：

`HuilvsudiCmbProvider`

后续可以扩展：

- 招商银行官方行情源（如取得合法稳定接口）
- 上海黄金交易所市场参考行情源
- 其他银行积存金行情源

不同来源的价格不能混为同一序列，也不能无提示自动切换后继续触发原有交易规则。

## 5. 系统托盘功能

### 5.1 macOS 菜单栏

默认显示：

```text
Au  ¥838.70  ↑0.68
```

可配置显示模式：

1. 简洁模式：`¥838.70`
2. 标准模式：`Au ¥838.70`
3. 完整模式：`招行 ¥838.70 ↑0.68`

这里的涨跌数值仅在确认接口 `change` 字段的实际含义后显示。

刷新价格时同步更新菜单栏内容。

macOS 菜单栏使用原生托盘接口设置文本标题，不通过重复创建图标实现。

当行情过期时，显示：

```text
Au ¥838.70 · 已过期
```

当没有任何有效数据时：

```text
Au --.--
```

### 5.2 Windows 系统托盘

默认使用黄金图标。

推荐优先实现：

- 托盘图标常驻。
- 鼠标悬停显示当前参考价格。
- 左键点击打开行情弹窗。
- 右键点击打开功能菜单。

Windows 由于系统托盘显示空间及API差异，不能保证常驻完整文字价格。

可以额外提供**可选桌面悬浮行情条**，满足Windows用户持续看到数值的需要。

### 5.3 托盘交互

左键点击：

打开或关闭行情弹窗。

右键点击：

```text
GoldTray
-----------------------
招商银行黄金活期
当前参考价：838.70

打开行情
预警管理
持仓管理
立即刷新
-----------------------
设置
退出
```

注意：部分平台的托盘左键、右键交互可能不同，需要使用平台适配实现。

### 5.4 应用生命周期

- 点击窗口关闭按钮：隐藏窗口，继续托盘运行。
- 点击托盘退出：真正结束进程。
- 系统登录：根据设置决定是否自动运行。
- 禁止多开：同时只允许一个程序实例。
- 系统休眠：停止无意义的轮询。
- 恢复运行：重新获取行情。

## 6. 价格预警管理

### 6.1 功能目标

支持用户创建多条独立预警规则，不限制为一个上涨或下跌价格。

### 6.2 预警规则模型

```typescript
interface PriceAlert {
  id: string;
  name: string;

  productCode: string;

  direction: "ABOVE" | "BELOW";

  priceType:
    | "CUSTOMER_BUY"
    | "CUSTOMER_SELL";

  targetPrice: string;

  enabled: boolean;

  triggerMode:
    | "ONCE"
    | "REARMABLE";

  cooldownMinutes: number;

  lastTriggeredAt?: string;
  lastTriggeredPrice?: string;

  createdAt: string;
  updatedAt: string;
}
```

字段说明：

- `ABOVE`：价格达到或高于设定值。
- `BELOW`：价格达到或低于设定值。
- `CUSTOMER_BUY`：客户买入报价。
- `CUSTOMER_SELL`：客户卖出报价。
- `ONCE`：触发一次后自动禁用。
- `REARMABLE`：价格离开触发区域后可重新激活。

### 6.3 预警判断逻辑

对于下跌预警：

```text
当前价格 <= 目标价格
```

对于上涨预警：

```text
当前价格 >= 目标价格
```

默认采用阈值穿越触发，而非价格持续满足条件就不断发送通知。

若规则创建时价格已经满足触发条件，标记为“已处于目标区间”，默认不立即触发；等待离开并重新进入区间，或者允许用户手动选择立即检查。

对于可重复规则：

- 首次穿越触发后进入已触发状态。
- 价格恢复到安全侧并达到回滞幅度后重新激活。
- 冷却时间内禁止重复通知。
- 应用重启后保持触发状态。
- 连续两次有效行情满足条件可作为默认确认机制。

### 6.4 示例预警配置

以下规则用于初始化示例，用户可以随时修改或删除。

| 规则名称 | 类型 | 价格 |
|---|---|---:|
| 第一轮加仓观察 | 客户买入价下跌 | 835.00 |
| 第二轮加仓观察 | 客户买入价下跌 | 805.00 |
| 第一档止盈观察 | 客户卖出价上涨 | 925.18 |
| 第二档止盈观察 | 客户卖出价上涨 | 959.45 |
| 第三档止盈观察 | 客户卖出价上涨 | 1010.85 |

注意当前数据源仅提供客户买入参考价。

因此，V1.0 对客户卖出价规则提供以下处理方式：

1. 如果没有卖出价数据源，规则默认显示“无法准确监控”。
2. 可允许用户手动启用“固定价差估算提醒”。
3. 估算价差由用户填写，例如5元/克。
4. 估算提醒只提示用户打开银行App核对，不宣称已经达到实际可卖出价格。

例如：

```text
客户卖出价目标：925.18
假设价差：5.00
客户买入参考价监控值：930.18
```

该换算只用于辅助提醒。

### 6.5 通知样式

示例：

```text
GoldTray · 黄金价格提醒

招商银行黄金活期参考买入价
已达到 835.00 元/克观察区间

当前参考价：834.80 元/克

建议先查看招商银行App，
确认实际价格及市场趋势。
```

通知不直接输出“必须买入”“立即卖出”等交易指令。

## 7. 持仓管理

### 7.1 核心功能

允许用户手工维护黄金账户交易记录。

支持：

- 买入记录
- 卖出记录
- 当前持仓
- 持仓均价
- 持仓成本
- 已实现收益
- 未实现盈亏
- 交易历史

V1.0 不连接个人银行账户。

### 7.2 交易记录模型

```typescript
interface GoldTransaction {
  id: string;

  productCode: string;

  type: "BUY" | "SELL";

  tradeTime: string;

  pricePerGram: string;
  quantityGram: string;

  grossAmount: string;
  feeAmount: string;

  remark?: string;
}
```

金额和克数由用户输入或计算。

买入交易允许：

- 输入交易金额和单价，自动计算克数。
- 输入黄金克数和单价，自动计算金额。

允许用户覆盖计算值，以匹配银行实际成交份额和金额。

### 7.3 持仓计算

初始支持移动加权平均成本法。

```text
黄金份额 = 累计买入份额 - 累计卖出份额

买入后总成本 =
原持仓成本 + 本次买入金额 + 买入费用

买入后平均成本 =
买入后总成本 / 买入后黄金份额
```

卖出时按卖出数量对应的加权平均成本结转，不把卖出后的剩余成本简单设为累计净投入金额。

```text
本次已实现收益 =
实际卖出收入
- 卖出费用
- 对应卖出黄金的账面成本
```

未实现盈亏：

```text
未实现盈亏 =
持有黄金份额 × 客户卖出价
- 剩余持仓账面成本
```

如果只能取得客户买入价：

- 不直接显示精确实时盈亏。
- 可以显示“基于价差估算”的盈亏。
- 必须标识估算状态。

数值计算使用 Decimal 类型或Rust十进制库，避免直接使用二进制浮点数累计交易金额。

### 7.4 初始示例持仓

提供可修改的示例数据：

```text
银行：招商银行
产品：黄金账户·活期

总投资预算：10000元
首笔买入：2000元
买入单价：856.65元/克
买入份额：约2.3347克

剩余计划预算：8000元
```

该数据为当前需求示例，不应该作为所有新用户的默认真实持仓。

实际产品首次启动应进入持仓初始化流程，允许跳过。

### 7.5 预算与交易记录区分

应用应分别保存：

- 用户设置的总投资预算
- 历史累计买入金额
- 当前持仓账面成本
- 历史累计卖出收入
- 用户实际可用资金（可选手工维护）

不能简单通过“总预算减去累计买入金额”推断卖出后仍可使用的现金。

## 8. 历史行情

### 8.1 行情存储

每次获取成功的报价记录：

```typescript
interface QuoteHistory {
  id: number;
  source: string;
  productCode: string;

  buyPrice: string;
  sellPrice?: string;

  fetchedAt: string;
  quotedAt?: string;
}
```

### 8.2 数据存储策略

V1.0 建议：

- 内存保留最新行情。
- SQLite按可配置采样频率保存历史数据。
- 默认每5分钟最多保存一笔有效行情。
- 相同时间片内不重复保存相同数据。
- 保留90天详细行情。
- 超过90天可保留日级聚合数据。

### 8.3 图表功能

支持以下时间范围：

- 最近1小时
- 最近24小时
- 最近7天
- 最近30天
- 最近90天

图表应使用真实采集的历史记录。

## 12. 异常处理

### 12.1 网络异常

- 不清空最后一次有效报价。
- 标记“数据已过期”。
- 记录最近成功获取时间。
- 停止对过期数据触发新增价格提醒。
- 网络恢复后重新拉取行情。

### 12.2 第三方接口异常

包括：

- HTTP异常
- JSON结构变化
- 产品记录缺失
- 字段类型变化
- 数据源长时间不更新
- 限流或访问受限

处理原则：

**显示明确错误，不使用估算价格冒充实时价格。**

### 12.3 精度控制

所有金额与黄金克数计算使用十进制计算库。

建议：

- 展示金价：2位小数
- 黄金份额：4～6位小数
- 金额展示：2位小数
- 内部计算：保留更高精度
- 最终显示时统一进行舍入

### 12.4 日志与隐私

日志不得记录：

- 银行登录凭证
- 身份证号
- 银行卡号
- 个人身份敏感信息

默认本地保存，不主动上传用户持仓数据。

避免把第三方网页中获取的设备标识、追踪ID作为长期固定请求参数。

## 13. 安全及合规

1. 所有行情请求通过HTTPS发送。
2. 不要求用户提供银行账号和密码。
3. 不存储银行App的Cookie、Token。
4. 不绕过第三方接口的鉴权、限流或访问控制。
5. 应确认第三方接口的使用条款，尤其是自动访问频率和软件分发许可。
6. 不自动执行任何实际交易。
7. 明确区分市场参考价、银行买入价和银行卖出价。
8. 应用只提供行情展示和提醒，不对盈利作出保证。
9. 外部接口访问范围在Tauri权限及网络策略中最小化配置。
10. 程序更新使用签名验证。

目前的汇率速递接口应定位为“经过初步验证的第三方数据源”，而不是获得正式授权的长期生产级行情服务。

## 17. 关键风险与待解决问题

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 汇率速递接口变更 | 无法获取行情 | 独立Provider模块、明确异常提示 |
| 数据源限制自动调用 | 无法持续监控 | 遵守条款，降低调用频率或更换授权来源 |
| 数据源不提供卖出价 | 无法准确计算即时可赎回盈亏 | 提供手工录入或明确标记的估算模式 |
| 第三方行情延迟 | 可能错过触发点 | 显示采集时间，禁止夸大实时性 |
| Windows托盘限制 | 无法完整展示价格文字 | 使用托盘提示、弹窗和可选悬浮条 |
| 交易所休市 | 行情长期不变 | 支持休市状态，不误判为接口故障 |
| 多平台打包差异 | 安装、通知或签名失败 | 双平台CI及真机测试 |
